BLAS in Go, with the Fortran signatures.
Column-major, SIMD, an error bound.

go-blas is the reference BLAS for Go: real (float32/float64) level 1, gemv and gemm, parameter for parameter as in Fortran, so that a Fortran ABI shim can call it exactly. Dgemm and Sgemm run on a SIMD kernel on six architectures, every routine states its error bound and checks it against a 256-bit oracle, and a bad argument is an error, never a panic.

Why go-blas

The BLAS Fortran code expects, in Go.

Numerical code that is written against BLAS expects the reference's conventions: column-major storage, leading dimensions, increments, the scalar rules and quick returns. go-blas keeps them all, so a caller written for netlib gets the same call and the same semantics. What it adds is a contract stated as a number: each routine's error is bounded elementwise and the bound is asserted in the tests, not assumed.

📐

Reference signatures

One routine per Fortran routine, with the s/d prefix convention (Dgemm, Sgemv, Idamax). beta = 0 never reads C, and alpha = 0 never reads A or B.

🎯

An error bound, not bit identity

For Dgemm, elementwise, |Ĉ − C| ≤ γk+2 (|α||op(A)||op(B)| + |β||C|), asserted against a math/big oracle of 256 bits. FMA, blocking and reordered sums are used inside it.

🛡️

No routine panics

A bad argument comes back as a *blas.ArgError with xerbla's parameter number. A slice shorter than the call needs is reported against its own parameter, also on 32-bit targets.

⚡

SIMD GEMM on six architectures

AVX2/FMA, NEON, VSX, LASX, RVV and the z vector facility, moved from go-ndarray/ndarray. The column-major product is the row-major product CT = op(B)T op(A)T, so one strided kernel serves both layouts.

🧮

The exact option

Package netlib is reference BLAS 3.12 in plain Go, in the reference's loop order and without FMA. Callers who need netlib's exact rounding use it.

🧪

Tests that bite

A fuzz target per routine with a committed corpus, 100% block coverage, and a tool that disables each argument guard in turn and requires an assertion to fail.

Speed

Not measured yet, so not claimed.

The GEMM kernel is the one go-ndarray measures, but nothing has been timed here against OpenBLAS yet, so this page makes no performance claim. When the table exists, wins and losses will be on it, one core against one core.

Next

What comes after v0.1.0.

Level 3

The rest of level 3 beyond the product.

LAPACK

getrf, potrf, geqrf and the routines around them, under the same naming and error conventions.

Complex types

The c and z routines (Cgemm, Zgemm, Zgemv, Zdotc/Zdotu) on complex64 and complex128 slices, added without breaking the real API.

The design was agreed on go-embedded-ruby/ruby#918 and is recorded in docs/design.md. Julia binds it through libblastrampoline (go-embedded-julia/julia#67), and go-ndarray will consume it in a later pull request.
